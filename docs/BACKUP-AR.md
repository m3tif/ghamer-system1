# النسخ الاحتياطي قبل أي تغيير خطير

**القاعدة:** لا تشغّل أي ملف SQL جديد (012 / 013 / 014) ولا استيراد كبير قبل نسخة احتياطية.

## الطريقة 1 — من لوحة Supabase (الأسهل)
Database ← Backups ← **Create backup / Download** (أو Point-in-time لو الخطة تدعمه). تأكد أن النسخة ظهرت بتاريخ اليوم قبل المتابعة.

## الطريقة 2 — من جهازك
```bash
DATABASE_URL_ADMIN="postgres://postgres:كلمة_السر@HOST:5432/postgres" ./scripts/backup.sh
```
ينتج ملف `backup-التاريخ.dump`. للاسترجاع: `pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL_ADMIN" الملف.dump`.

## قبل المايجريشن
- 012 يستبدل قيد «الرقم + النوع فريد» بفهرس فريد **للأرقام فقط** (الروابط والأسماء لم تعد تمنع). يفحص أولًا أنه لا يوجد رقم مكرر ويتوقف برسالة واضحة لو وجد.
- 013 و014 يضيفان جداول وأعمدة فقط ولا يغيّران أي بيانات موجودة.
- الأرقام القديمة **لا تُعدَّل**؛ فقط عمودان جديدان (الرقم كما كُتب + الدولة) يمتلئان للأرقام الجديدة.

## بعد أي استيراد
كل عملية استيراد مسجلة (من/متى/كام صف) ويمكن التراجع عنها من صفحتها (إخفاء ناعم بلا حذف). النسخة الاحتياطية تبقى هي الضمان الأخير.
