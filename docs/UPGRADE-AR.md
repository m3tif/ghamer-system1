# ترقية نظام يعمل بالفعل إلى النسخة المحسّنة (Migration 008)

التحديث **لا يحذف أي بيانات**. يحوّل أسماء الحالات القديمة إلى الجديدة، ويضيف الأعمدة والجداول والفهارس، ويمكن تشغيله أكثر من مرة بأمان.

## قبل البدء (5 دقائق)
1. **نسخة احتياطية:** Supabase ← Database ← Backups ← خذ نسخة (أو تأكد من وجود نسخة اليوم). لا تكمل قبل ذلك.
2. تأكد أن `DATABASE_URL` في Vercel يبدأ باسم المستخدم **`ghamer_app.`** وليس `postgres.` (انظر القسم التالي).

## الخطوات
1. من جهازك، في مجلد المشروع بعد سحب آخر نسخة:
   ```bash
   export $(grep -v '^#' .env.local | xargs)   # يحتوي DATABASE_URL_ADMIN و APP_DB_PASSWORD
   npm install
   npm run db:migrate
   ```
   سيطبّق الملف `008_phase1_refinement.sql` فقط، لأن الملفات السابقة مسجَّلة عنده.
2. **بديل بدون Terminal:** افتح Supabase ← SQL Editor، والصق محتوى `db/migrations/008_phase1_refinement.sql` كاملًا وشغّله، ثم شغّل:
   ```sql
   insert into schema_migrations(name) values ('008_phase1_refinement.sql') on conflict do nothing;
   ```
   (إن لم يكن الجدول `schema_migrations` موجودًا فتجاهل السطر الثاني، فقد أنشأت الجداول من المحرر مباشرة.)
3. ارفع الكود الجديد إلى GitHub. سيعيد Vercel النشر تلقائيًا، ويبدأ تشغيل الدوال من **فرانكفورت** بجانب قاعدة البيانات (ملف `vercel.json`)، وهذا وحده يسرّع الصفحات كثيرًا.
4. افتح `https://<موقعك>/api/health` ويجب أن ترى `{"ok":true,"role":"restricted"}`.

## لماذا كانت بيانات الموظفين تظهر لبعضهم؟
قواعد الخصوصية تعمل داخل قاعدة البيانات، لكنها **لا تسري على مستخدم قاعدة البيانات `postgres`** (يتجاوزها بالتصميم).
إن كان `DATABASE_URL` في Vercel يستخدم `postgres.xxxx` بدل `ghamer_app.xxxx`، فكل موظف يرى كل شيء رغم سلامة الكود.
النسخة الجديدة **ترفض العمل** إن اتصلت بمثل هذا المستخدم، وتعرض خطأً واضحًا بدل أن تكشف بيانات.

الصيغة الصحيحة:
```
postgres://ghamer_app.<project-ref>:<APP_DB_PASSWORD>@aws-1-eu-central-1.pooler.supabase.com:6543/postgres
```
(أي رمز خاص في كلمة المرور يُكتب مشفّرًا، مثل `&` ← `%26`.)

## ما الذي تغيّر في سلوك النظام
- حالات العميل الجديدة: عميل جديد، تم التواصل، لم يرد، مهتم، غير مهتم، يحتاج متابعة، عميل مؤهل (+ تم حجز اجتماع / تم الاجتماع / بيانات غير صالحة). الحالات القديمة حُوِّلت تلقائيًا (معاودة اتصال ومتابعة لاحقًا ← يحتاج متابعة).
- **بعد تحويل العميل إلى Sales لا يظهر ملفه لـ Tele Sales**، وتتابع نتيجته (الاستلام، الاجتماع، الصفقة) من تبويب «تم تحويلها». يبقى اسمها كمُسجِّلة أصلية.
- العملاء الذين كانوا مسندين لـ Sales بالفعل حُوِّلوا تلقائيًا إلى هذا النظام مع حفظ تاريخهم.
